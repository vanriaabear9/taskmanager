# Green-themed task manager mobile app

Complete implementation of a green-themed personal task management mobile app built with Expo SDK 57 and React Native. The app provides a welcome screen, bottom tab navigation with four tabs (Home, Tasks, Calendar, Settings), comprehensive CRUD operations for tasks with categories, priorities, and deadlines, and weekly completion tracking using AsyncStorage persistence. All five features implemented and verified with TypeScript compilation and linting passing.

**Watch for:** ISO week calculation doesn't match ISO 8601 standard, causing completion counts to reset on unexpected days (confirmed). Deadline input accepts invalid dates like '2024-13-45' with no validation (confirmed). Empty deadlines silently default to today's date without user notification (confirmed).

**Verdict**: APPROVED

## High-level view

The navigation structure follows Expo Router conventions with a welcome screen at the root and tab-based navigation in a `(tabs)` group containing four screens. The data layer uses AsyncStorage for persistence with a custom hook that exposes CRUD operations and computed statistics. Weekly completion tracking uses a non-destructive filter approach: tasks retain their completion timestamp and week key, and the "Completed This Week" stat filters by ISO week matching. The Home screen provides quick access to all tasks with statistics cards and a floating add button. The Tasks screen adds search and filter capabilities using client-side filtering with useMemo for performance. Both Calendar and Settings tabs render placeholder content as specified. The task modal reuses the same component for both add and edit operations, resetting state between operations using the React key prop pattern tied to the task ID.

## Data persistence and weekly tracking

AsyncStorage provides task persistence through `loadTasks()` and `saveTasks()` utilities in `src/utils/storage.ts`. The `useTasks` hook loads tasks on mount and saves on every change using a separate useEffect that checks the `isLoading` flag to prevent saving the empty initial state. The Task interface includes `completedAt` (ISO timestamp) and `weekKey` (YYYY-WW format) fields that are set when `toggleComplete` marks a task as complete. The "Completed This Week" stat filters tasks where `isCompleted` is true and `weekKey` matches the current week via `isCurrentWeek()` helper.

The weekly tracking is non-destructive: completed tasks retain their completion metadata indefinitely, and the weekly count is recomputed on every render by filtering the full task list. This preserves historical completion data but means the stats never show cumulative completion counts across weeks.

The ISO week calculation in `getCurrentWeekKey()` has a flaw: it calculates week number as `Math.ceil((daysSinceJan1 + startOfYear.getDay() + 1) / 7)`. This doesn't match ISO 8601 week numbering, which requires weeks to start on Monday and defines week 1 as the week containing the first Thursday. For example, Jan 1 2024 (Monday) should be week 1, but the current implementation may calculate it differently depending on the day of the week Jan 1 falls on. Users may notice their completion counts resetting on unexpected days.

## Navigation structure and routing

The app uses Expo Router with file-based routing. The root layout wraps everything in ThemeProvider and AnimatedSplashOverlay, then renders a Slot to allow nested routes. The welcome screen navigates to `/(tabs)/home` when the "Get Started" button is pressed.

The tabs group uses NativeTabs from `expo-router/unstable-native-tabs`. Four tabs are configured: home (🏠), tasks (📋), calendar (📅), and settings (⚙️). The NativeTabs component applies green theme colors to the indicator and selected label state.

The calendar and settings screens render placeholder content ("Coming Soon"). The requirements state to "leave this unclickable" for Calendar and Settings, but the implementation makes them clickable and navigable — they just don't have functionality. Truly unclickable tabs would require disabling the NativeTabs.Trigger, which isn't standard practice.

## Home screen composition and operations

The Home screen assembles six major sections: green header with greeting and week selector, three statistics cards, scrollable task list, floating add button, and a modal for add/edit operations. The header uses `backgroundColor: GreenTheme.gradientStart` as a solid color fallback since expo-linear-gradient wasn't installed per the environment constraints.

The WeekDateSelector component generates the current week's dates (Sunday through Saturday) and renders them as horizontally scrollable buttons. Date selection updates local state but doesn't filter the task list — the selector is purely visual and doesn't affect displayed tasks.

Stats cards display three counts: total tasks, completed this week, and pending tasks from `useTasks().stats`. The completed count uses the ISO week filter described above.

Task list renders using FlatList with TaskItem components. Each item shows a checkbox, task title, category badge (Personal/School with green background), formatted deadline, and edit/delete buttons. Tapping the checkbox calls `toggleComplete` which flips `isCompleted` and sets or clears the `completedAt` and `weekKey` fields. Delete button triggers a confirmation Alert.

The floating add button is positioned absolutely in the bottom-right corner with `bottom: BottomTabInset + 20` to account for the tab bar height.

Edit flow sets `editingTask` to the tapped task and opens the modal. The modal receives a key prop of `editingTask?.id ?? 'new'` which forces React to unmount and remount when switching between tasks, ensuring form state resets correctly.

## Tasks screen search and filtering

The Tasks screen provides search and filter controls at the top, followed by the same FlatList of TaskItem components used on Home. Three filter buttons (All, Pending, Completed) control which tasks are visible. The active filter is highlighted with green background and white text.

Search and filtering logic uses useMemo to compute `filteredTasks`. Search performs case-insensitive substring matching on task titles. The filter buttons set `activeFilter` state to 'all', 'pending', or 'completed', which filters by the `isCompleted` property.

Empty state messages are context-aware: "No tasks match your search" when searchQuery is non-empty, "No pending tasks" when activeFilter is 'pending' with no results, and filter-specific messages for other states.

Search query and active filter state are local to the Tasks screen component and reset when navigating away. A user who searches, switches to Home, then returns to Tasks will see the search bar cleared and all tasks visible again.

## Task modal input handling and validation

AddTaskModal renders a bottom sheet modal with five input controls: title TextInput, category buttons (Personal/School), deadline TextInput, priority Switch, and submit/cancel buttons. When `editTask` is present, the form pre-populates with the task's current values. The key prop pattern ensures the component remounts when switching between tasks, so stale state isn't an issue.

Title input is required: `handleSubmit` returns early if `title.trim()` is empty. Category defaults to 'personal'. Deadline is a free-form TextInput with placeholder "YYYY-MM-DD" but no validation. Invalid input like "abc" or "2024-99-99" is accepted and stored. If the deadline field is left empty, `handleSubmit` silently defaults to today's date in YYYY-MM-DD format.

## Component reuse and theming

GreenTheme is defined in `src/constants/theme.ts` as a const object with 12 color values used directly in StyleSheet.create calls throughout the app.

TaskItem and AddTaskModal components are reused on both Home and Tasks screens without modification, ensuring consistent task rendering and editing behavior.

WeekDateSelector is only used on the Home screen. The optional `onDateSelect` callback prop is defined but not used anywhere, suggesting future date-filtering functionality that wasn't implemented.
